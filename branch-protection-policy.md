# Регламент защиты веток для учебной команды из 4 человек (Вариант 4)

## 1. Защищаемые ветки и правила
| Ветка | Обязательные правила |
|---|---|
| main | PR обязателен; 1 одобрение; Dismiss stale approvals; статус-проверка `test` + актуальность ветки; запрет force push и удаления; Require linear history; Include administrators |
| develop | PR обязателен; 1 одобрение; статус-проверка `test`; запрет force push и удаления |
| release/* | как у main; слияние разрешено только тимлиду (Restrict who can push) |

## 2. Число одобрений
- main — 1 одобрение. В команде из 4 человек 2 одобрения на каждый PR заняли бы половину команды и тормозили бы работу; одного внимательного ревьюера достаточно, т. к. дополнительно действует CI.
- develop — 1 одобрение: ветка интеграции, ошибки здесь дешевле, но код всё равно должен увидеть второй человек.

## 3. Стратегия слияния
Разрешён только **Squash and merge**: каждая задача попадает в main одним коммитом с сообщением по Conventional Commits, «черновые» коммиты (wip, fix typo) не засоряют историю, история остаётся линейной и совместимой с Require linear history.

## 4. Срочное исключение (emergency bypass)
1. Решение об обходе принимает тимлид, причина фиксируется в issue с меткой `incident`.
2. Тимлид временно снимает флаг Include administrators (или нужное правило), выполняет слияние через PR с пометкой `[EMERGENCY]`.
3. Сразу после слияния настройки защиты восстанавливаются, проверяется их конфигурация (`gh api repos/<repo>/branches/main/protection`).
4. В течение 1 рабочего дня проводится ретроспективное ревью слитого кода; найденные замечания оформляются задачами.
